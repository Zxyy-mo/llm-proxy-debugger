# Request export and replay contract

## Sources and captured metadata

Every capture keeps two snapshots: `original` (what the client sent to the gateway) and `outgoing` (what the transport sent upstream, including the upstream path prefix and all rule modifications). Each snapshot records a private forwarding profile — scheme, host, decoded/escaped path, credential-free query, and every forwardable header with all of its values — plus the names of the credentials it carried. Credential values are never stored: header credentials (`Authorization`, `X-Api-Key`, cookies and any header whose name suggests a token, key, secret or signature) and secret query parameters (`key`, `api_key`, `token`, …) are removed at capture time, and `RequestLog.query` and snapshot URLs mask secret parameter values as `****`. The public snapshot JSON exposes `credentials: [{kind, name, scheme?, replayable}]`; the forwarding profile itself is `json:"-"` and only used by the export and replay code paths. Hop-by-hop headers, headers listed in `Connection`, `Forwarded`/`X-Forwarded-*`/`Via`, `Host` and `Content-Length` are excluded because they describe one hop rather than the request.

`source` is always explicit in the API (`original` or `outgoing`); the default is `outgoing` when it exists, otherwise `original`. A request that never reached the upstream has no outgoing snapshot and must be refused explicitly, never silently substituted.

## cURL export

`GET /api/requests/{trace_id}/curl?source=…` returns `{trace_id, source, shell: "posix-sh", destination: {kind, url}, command, body_mode, body_file?, body_bytes, environment: [], notes: []}`. `destination.kind` is `gateway` for original snapshots (host from the captured `Host`, or the listen address mapped to loopback when unspecified) and `upstream` for outgoing snapshots. Commands never target the Vite origin.

Every untrusted value (URL, header values, body) is single-quoted; words that reference a credential placeholder use double quotes only when their literal parts contain no `"`, `$`, backtick, backslash, `!` or newline, otherwise adjacent single-quoted and double-quoted pieces. Credentials become `${REPLAY_<NAME>}` placeholders (`REPLAY_AUTHORIZATION`, `REPLAY_QUERY_KEY`, `REPLAY_URL_USERINFO`, …) listed in `environment` with their scheme; masked display values are never used. Signed schemes (AWS4-HMAC-SHA256, Digest, HMAC, OAuth, Negotiate/NTLM, or values carrying `Signature=`/`Credential=`) are exported as placeholders with `replayable: false` and a note. Missing `Accept`, `User-Agent` and `Content-Type` are explicitly emptied so curl adds no defaults, and `Expect:` is suppressed for bodies.

`body_mode` is `none`, `inline` (UTF-8 text up to 64 KiB without NUL bytes) or `file`. File mode references `body_file` (`replay-<8 chars>-<source>.json|.bin`) and `GET /api/requests/{trace_id}/body?source=…` downloads the exact bytes (base64 snapshots decoded) with that file name. Copy and export never send a request. Unknown traces return 404, invalid `source` 400, a missing outgoing snapshot 404, non-GET 405, and captures without forwarding metadata 422.

## Replay

`POST /api/replays` accepts `{trace_id, source?, body?, headers?, credentials?, idempotency_key, timeout_seconds?}`; unknown fields, trailing JSON and bodies over 16 MiB are rejected (400/413). `idempotency_key` (1–200 characters) is required: the same key with the same content returns the existing record with 200 and never executes again; the same key with different content returns 409; a new key executes again. `timeout_seconds` defaults to 600 (1–3600).

Only `POST` requests to `/messages`, `/chat/completions` or `/responses` may be replayed (422 otherwise); WebSocket captures cannot be replayed by this API. Outgoing snapshots are pinned to their captured Provider (or default target), scheme/host and base path, including escaped path bytes. A removed Provider or changed destination returns 409. The prefix is applied exactly once; rules, breakpoints, model aliasing, protocol conversion and fallback selection are not repeated. Original snapshots re-enter the current pipeline like new client requests. The bypass and replay identity travel in server-owned context, not client headers.

`body` replaces the complete body and `headers` replaces the editable header subset (`Content-Type`, `Accept`, `Anthropic-Version`, `Anthropic-Beta`, `OpenAI-Beta`); omitted edits send the captured bytes exactly. Edits are validated with the interception rules (JSON object, protocol structure, local tool pairing, immutable session/conversation/thread identifiers and parent references); compressed or non-UTF-8 bodies can only be replayed unchanged. `credentials` supplies `{kind: header|query|url, name, value}` for this replay only: required captured credentials must be provided unless replaced by the selected Provider's environment key (missing ones are listed in a 422); values must be 1–8192 printable characters, not contain `****`, and name a credential header, a secret parameter or `userinfo` (rendered as Basic authentication). Signed credentials cannot be replayed. Supplied values are set on the outgoing request and discarded; they never enter logs, snapshots, exports, graph data or browser storage. `POST /api/replays/validate` runs the same planning without executing and reports `missing_credentials` instead of failing on them.

Execution runs on a server-owned context bounded by the timeout, independent of the creating HTTP request, through the normal proxy pipeline (capture, correlation, SSE recording, live events). The management caller receives the execution record; the recorder saves the full model response separately. Creation answers 202 once the new trace exists. `GET /api/replays` lists records, `GET /api/replays/{id}` returns one, `POST /api/replays/{id}/cancel` cancels a running replay (409 with the record if already finished, 404 if unknown). Records carry `id`, `trace_id`, `replay_of`, `source`, `modified`, `state` (`running`, `done`, `error`, `canceled`), `reason` (`manual`, `timeout`, `shutdown`, or `gateway_restarted`), `error`, `status_code`, `created_at`, `finished_at`, `timeout_seconds` and `idempotency_key`. A manual cancellation logs status `canceled` with 499; a replay deadline logs status `error` with 504 and is not reported as a client cancellation. The hub publishes `replays_updated` on every record change. Nothing is executed automatically after a restart, a page reload or a reconnect.

## Persistence, privacy and Provider credentials

The forwarding profile is private to the server and persisted alongside request metadata, including Provider ID, base URL and RawPath; it contains no credential values. Request bodies are file-backed and loaded on demand. Response content is saved separately and can be compared with the source via [response APIs](response-metrics.md).

When a selected Provider has `key_env` configured, replay obtains its supported authentication header from that process environment and validation does not ask the UI for the replaced captured key. Other required captured credentials still need transient input. A capture whose original body was discarded by privacy policy is refused for exact replay; supplying a complete replacement is a separate validated edit.

Replay records, fingerprints and idempotency keys are committed synchronously before a new persistent replay starts. Manager mutations publish ordered snapshots; notifications do not independently overwrite saved replay state. Concurrent submissions of the same key wait for registration to finish and create at most one execution. Registration save failure returns 503, rolls back the rejected setting/key and sends no upstream request; an explicit retry can succeed after storage recovers. A closing replay manager rejects new keys with 503, and an execution canceled by gateway shutdown reports `reason:shutdown` separately from manual cancellation.

Registered keys remain effective after restart; saved running records become `error` / HTTP 503 with `reason:gateway_restarted`. Ordinary completion/metric updates remain coalesced. A crash after the registration commit but before dispatch can leave an interrupted replay without a captured model trace, and a crash after dispatch can leave its final outcome unknown. This is durable registration and at-most-once execution per accepted key, not exactly-once completion. Memory-only mode has no restart durability. History cleanup does not automatically re-execute or forget recorded replay actions.

## Provenance

每个服务器确认的新重放动作还创建独立 Run，`run.state:replay`。原始报文中的旧 Run 证据保持原字节，但不再决定这次执行的观测归属；同一幂等键仍指同一重放任务。任务与逐次出站兼容边界见 [四层契约](call-layers.md)。

The replayed request is a new trace whose log and graph node carry `replay: {id, of, source, modified}`. Provenance is not parent evidence: `correlation` keeps only real identifiers, `previous_response_id`, parent references and history matches. A replay without its own conversation evidence joins the source's session with `session_source: "replay"`; explicit identifiers and parent references keep priority. The graph adds an edge with `kind: "replay"` from the source trace (as a reference node when it lives elsewhere) and the UI draws it dotted and distinct from parent edges. Source records, captures and interception state never change.

## Required verification

- Good: export both sources of a request with header and query credentials, run the commands with the real curl binary and environment values, and confirm byte-identical bodies, credentials, preserved multi-value headers and correct destinations; replay an edited outgoing snapshot with transient credentials and confirm one upstream call with one injection, provenance on the new log and graph, and untouched source records.
- Base: an unedited replay resends the captured bytes (including base64-encoded bodies and large integers); validation succeeds before credentials are entered; a retry with the same idempotency key executes once.
- Bad: invalid JSON, changed identifiers, non-editable headers, masked credential values, non-credential names, mismatched destinations, non-generating requests, never-forwarded outgoing sources and signed schemes are refused without executing; manual cancellation and deadlines reach terminal states and stop the upstream request; no gateway artifact (sessions, replays, captures, graph, exports, SSE dumps, logs) contains a supplied secret.
- Browser: copy equals the API command, the download equals the capture, the run button waits for credentials, cancel/timeout states render, inspector and graph show provenance, reload creates nothing, and copy/run/validate/credential controls stay reachable at the seven layout viewports.
