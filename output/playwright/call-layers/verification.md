# 四层调用模型与兼容接入集成验收

日期：2026-09-11。分支：`feat/agent-debugger-workflow`。上一轮确认文档已在 `98514cc` 推送；本报告记录后续功能实现的受控验收。

## 已交付

- `trace_id` 仍标识 Request，新增明确 Run 归属、未知/冲突状态、任务汇总与筛选。
- HTTP 和 Responses WebSocket 的真实上游 Attempt 独立记录身份、出站内容、响应头/结束计时和终态。
- 重放创建新 Run，原报文字节、来源关系和持久幂等登记保持；旧 `outgoing` 继续指最后一次发送。
- v3 保存逐次捕获，兼容 v1/v2，恢复活动尝试为 interrupted，不自动执行。
- 常用兼容上游的预设、能力声明、模型发现与路由应用；专项 UI 验收见 [兼容接入](../compatible-provider-setup/verification.md)。

## 自动检查

最终工作树通过 `go test -race ./...`、`go vet ./...`、`npm --prefix web test`（53 项）及 `npm --prefix web run build`（包含 Vue 类型检查）。

新增行为测试包括 Run 明确/缺失/重复/冲突证据、同轮分支、跨会话/上游/凭证隔离、编辑不可变、协议转换后的能力检查、模型列表鉴权/URL/错误/过期结果、HTTP/WS 尝试结束与取消、v1/v2→v3 恢复、隐私和文件清理。

独立跨层审查发现并关闭四个问题：WS 清理不能把上游失败改成取消；非 create 控制首帧同样检查能力；重复会话 JSON 证据不能生成明确 Run；Provider 配置加载/保存互斥。均有针对性复现或回归测试。

## 实际浏览器操作

[journey.js](journey.js) 在独立的本地网关和 [受控上游](mock_upstream.py) 上运行，17 项断言通过。种子会话包含两轮、同轮两个分支、缺失 Run 和冲突 Run，共 7 个模型请求、14 次实际发送；之后另有一次显式 UI 重放。

- 按任务筛选三个请求，画布仍保留完整七个请求节点和真实父子关系。
- 汇总显示三个请求、六次尝试；逐次查看主上游 503 和备用上游 200。
- 每份出站 URL、模型别名与 `9007199254740993` 字节保真，真实下载链接可用。
- 切换尝试、刷新、任务查询 500 和出站读取 500 的重试均不串读其他快照，也不增加上游调用。
- 缺失/冲突请求保持未关联；过滤不替换当前调查选择。

浏览器没有未捕获的运行时异常。网络失败场景主动注入两条 HTTP 500，因此控制台相应的资源失败日志属于验收预期。

[replay.js](replay.js) 的 11 项断言通过：空工作台来源刷新仍为空，工作台不被任务栏挤占，手机/短横屏编辑器保留至少 120 px 高度；实际点击原样重放只增加一次固定备用上游发送，新任务保留来源且正文完全一致；刷新结果不重复执行，临时密钥不进入浏览器存储。

## 真实进程中断与恢复

[restart_qa.py](restart_qa.py) 使用最终编译二进制、自有临时进程和目录；活动 SSE 尝试实际写入 SQLite 后终止进程，再从同一数据目录启动。18 项检查通过：3 个请求、5 个尝试身份恢复，5 份独立出站正文哈希一致，活动请求恢复为 503/中断，Attempt 为 interrupted 且结束时间和总耗时未知；已完成尝试保持原状态，重放幂等键跨进程有效，恢复/读取/同键重试均未补发模型请求。

独立浏览器网关也换为最终二进制并恢复既有会话，重新执行主流程验收通过。

## 复现入口与证据

结构化检查结果在 [results.json](results.json)。先构建前端和 Go，使用独立端口与临时日志目录启动 `mock_upstream.py --port <上游端口>` 和网关，再运行 `seed.py --gateway <网关地址> --upstream <模拟上游地址>`。在命名 Playwright CLI session 中依次执行 journey、layout 和 replay 脚本；重放脚本显式产生一笔新执行，其余只读脚本不产生模型调用。

进程恢复验证：`python3 output/playwright/call-layers/restart_qa.py --binary <已编译的网关路径>`。脚本只管理自己创建的进程，不停止其他开发服务。

本轮所有测试服务和浏览器 session 在交付前关闭。数据库、原始下载与 CLI 原始日志留在忽略的本地路径，版本控制只收录报告、脚本、结构化结果和合成截图。

## 边界

这里证明通用协议和本地观察/调试流程可用。尚无 CPA、New API、Sub2API、vLLM 对应真实实例的地址和凭证，不能称为四个平台已真实联调通过。中转内部执行、完整 Agent/MCP 工作流重放和自动 SDK 插桩仍未实现。
